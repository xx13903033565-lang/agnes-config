## 🔴 问题根因

### 现象
- **父会话上下文指数膨胀**：单会话 34,037 条消息（阈值 500 条）
- **每轮生成变慢**：CPU/GPU 功耗拉满，机器过热
- **日志文件巨大**：单个 main.jsonl 达 16MB

### 数据证据
| 指标 | 数值 |
|------|------|
| 当前会话消息数 | **34,037 条** |
| 安全阈值 | 500 条 |
| 超标倍数 | **68 倍** |
| 每场任务 delegate 次数 | 6-12 次 |
| 每次 delegate 带回 events | 数千条 |
| 日志文件大小 | 16MB/会话 |

### 根因链条
```
子代理 load 工具 
  → 返回全量 message events（硬编码在引擎二进制）
  → 父会话无条件注入这些 events
  → 每场任务 delegate×6-12 次
  → 上下文从几百条暴涨到数万条
  → LLM 每轮处理 34K+ 消息
  → CPU/GPU 功耗拉满 + 生成极慢
```

### 2️⃣ 子代理上下文节流器（已部署）
**文件**: `~/.agnes/rules/subagent_context_throttle.py`

**功能**：
1. **自动摘要**：子代理执行完后提取结论（⛔不回传全量 events）
   - 只保留最后一条 assistant 响应（最终结论）
   - 保留工具调用元数据（名称+参数，不保留返回值）
   - 保留 error/warning 消息
   
2. **上下文体积告警**：超过 500 条即警告，超过 1000 条自动裁剪

3. **智能裁剪**：
   - 保留最近 N 条消息（默认 200）
   - 强制保留所有关键工具调用
   - 自动生成备份文件

4. **按需 peek**：提供工具查看子代理全量日志统计（不加载全文）

**后台监控**：已启动（PID: 99834）

## 📊 长期方案评估

### 方案 A：应用层节流（✅ 已实施）
**优点**：

**缺点**：

#### 设计要点
1. **子代理结果结构化**
   ```typescript
   interface SubagentResult {
   ```

3. **上下文体积监控**
   - 引擎内部计数器
   - 超过阈值自动切换到摘要模式

### 裁剪策略
1. **保留最近 N 条**：确保上下文时效性
2. **强制保留关键工具**：delegate/load/write/shell 调用不可丢
3. **备份原文件**：防止误删，可随时恢复
4. **渐进式裁剪**：不会一次性砍到 0
